# ТЗ: «Канбат» — ИИ-помощник поддержки с канбан-доской обращений

> **Версия 4.14 (28.09).** **Вопросы — в панели внизу, как в Claude, и без абсурда.** Вопросы уточнения и встречные вопросы помощника показываются **внизу, на месте поля ввода**: «Вопрос 1 из 2», сам вопрос, пронумерованные варианты (клавиши 1–4) и последним пунктом — **«Свой ответ…»** с полем ввода; ниже — «Пропустить вопрос» и **«Ответить без уточнений»** (помощник отвечает с тем, что известно, называет допущения и больше не спрашивает). В переписке вопрос остаётся с пометкой «Ответьте в панели внизу». Вопросов — не больше 2 (срочно — 1), без повторов; вопрос задаётся, только если от ответа зависит совет; «Не знаю» больше не добавляется сервером к каждому вопросу; правило организации «уточняй…» — только если относится к обращению; «Сервис» в разборе — своими словами, не из примеров инструкции (пп. 4, 13).

> **Версия 4.13 (28.09).** **Единая инструкция помощника и этапы по смыслу ответа.** Все этапы (разбор, уточнение, шаги, ответ, разговор без обращения) строятся на одной базовой инструкции: кто помощник, как говорит, чего не делает; этап добавляет только свою задачу. Пока организация не настроена — **универсальный помощник поддержки** (без привязки к ИТ); профиль организации не спорит с основой, а сужает роль. После каждого ответа помощника сервер **оценивает ответ**: нужны данные → «Уточнение», сделана часть → «В работе», готово → «Проверка» — и подбирает **кнопки по смыслу** вместо «Принять / Доработать» («Для себя / Для ребёнка / По доверенности», «Да, записался / Не получилось записаться», «Понятно, спасибо / Нужно подробнее»). Новый режим разбора **«заявка»** (записаться, оформить, заказать). Правила организации «уточняй…» учитываются уже на разборе; срочность — только по тому, насколько горит; «Решено» текстом — только короткой репликой (пп. 3, 4, 13, 17).

> **Версия 4.12 (28.09).** **Профиль организации, шаг 1 — роль и характер помощника** (п. 17). Новая роль: **администратор организации** — специалист, вошедший с кодом администратора (`ADMIN_CODE`), в меню — «Организация». Там: шаблон отрасли (ИТ-поддержка компании, Центр госуслуг, Игровая платформа, Интернет-магазин, Свой вариант), название организации, имя и роль помощника, с чем он помогает, обращение («вы» / «ты»), тон (дружелюбный / деловой / краткий), вопросы не по теме (отвечать коротко / вежливо отказывать), **тонкости** — «Всегда» и «Никогда» (до 10 правил) и фраза в конце каждого ответа; «Проверить на вопросе» — пробный ответ по несохранённым настройкам. Правила действуют на разбор, уточняющие вопросы, шаги, ответы и разговор без обращения (пп. 15, 17).

## 1. Роль и цель

Ты — ведущий fullstack-разработчик и продуктовый дизайнер. Создай веб-приложение (адаптивное, desktop + mobile): ИИ-помощник, в котором каждое обращение пользователя — это **задача-карточка на канбан-доске**. Карточка сама движется по столбцам по мере того, как ИИ разбирает обращение и помогает довести его до результата. Любую карточку можно открыть как обычный чат.

Главная идея продукта (v4.0): **сотрудник просто пишет и видит путь своей заявки**, а **поддержка работает на канбан-доске** и получает готовую сводку. Экран сотрудника — «Мои обращения»: слева список (сначала «Нужен ваш ответ», затем «В работе», «Решённые» свёрнуты), справа чат; у каждого обращения — полоска из 5 этапов доски (Черновик → Уточнение → В работе → Проверка → Готово) и понятный статус. Канбан-доска для сотрудника остаётся как вид «Доска» (переключатель «Список / Доска» в шапке, выбор запоминается) — для тех, кто ведёт много обращений. Доска специалиста — основной рабочий инструмент поддержки (п. 14).

## 2. Классификация задач

При создании каждая задача автоматически классифицируется по двум осям (пользователь может поменять классификацию вручную):

|                                                                    | **Легковыполнимая**                                 | **Трудновыполнимая**                                                                       |
| ------------------------------------------------------------------ | --------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **Чётко структурированная** (ясная цель, критерии, входные данные) | **A** — быстрый проход, без остановок               | **B** — 1 контрольная точка: подтверждение плана                                           |
| **Слабо структурированная** (размытая цель, нет критериев)         | **C** — 1 контрольная точка: уточнение формулировки | **D** — 2–3 контрольные точки: уточнение цели, согласование плана, промежуточный результат |

- На карточке тип отображается бейджем: иконка структуры (■ чёткая / ◌ слабая) + индикатор сложности (1–3 деления). Рядом — бейдж **срочности** (п. 13).
- Классификация входит в разбор обращения (п. 13) — отдельный быстрый запрос к модели с ответом в JSON.

**Как определяется тип (v4.10):** структуру (чёткая / размытая) и сложность (лёгкая / трудная) при разборе ставит модель по правилу: лёгкая — одна причина и 1–3 действия, трудная — несколько симптомов или долгий поиск причины; чёткая — понятно, что не работает. Поверх — правила сервера: короткое обращение без подробностей и без вопросительной формы (≤ 5 слов, не срочное, режим «ответ») считается размытым и сначала уточняется («Что именно не получается и на каком шаге», «В какой программе или на каком устройстве»). Тип можно поменять вручную. Следующий этап — правила организации («Профиль организации»), важнее мнения модели.

## 3. Этапы обращения и столбцы доски

Обращение проходит **5 этапов** — у сотрудника они видны полоской этапов в списке и в чате, в виде «Доска» и у специалиста — столбцами:

1. **Черновик** — сырое обращение: пользователь пишет проблему своими словами. Здесь же подзона **«Запланировано»** для задач с таймером.
2. **Уточнение** — разбор обращения и уточняющие вопросы (только по недостающей информации).
3. **В работе** — решение: пошаговые действия пользователя или ответ ИИ; здесь же обращения, **переданные специалисту**.
4. **Проверка** — финальная стадия: работа выглядит завершённой, человек подтверждает результат. Кнопки — **по смыслу ответа** (v4.13): для заявки «Да, записался / Не получилось записаться», для консультации «Понятно, спасибо / Нужно подробнее», для проблемы по шагам — «Решено / Не помогло». Первая — в «Готово», вторая — доработка. Если модель кнопок не дала — запасные «Принять / Доработать» (окно «Что доработать?»).
5. **Готово** — решённые обращения: сюда карточка попадает **только после подтверждения человеком** (кнопка «доволен» в «Проверке», «Решено», «Закрыть обращение» или перетаскивание вручную).

**Куда идёт карточка после ответа помощника (v4.13)** — не по знаку «?», а по оценке ответа (отдельный короткий запрос к модели, запасная оценка — по тексту): помощник **просит данные или выбор** («уточните, для кого услуга») → «Уточнение», «Нужен ваш ответ», кнопки-варианты; **дал часть решения** и ждёт результата → «В работе», кнопки «получилось / нет» по смыслу; **ответ готов** → «Проверка». Вежливое «Помогло?» в конце готового ответа — не встречный вопрос.

**Направление движения:** слева направо; на мобильных — вертикальные секции: **Черновик сверху, Готово снизу** (секции сворачиваются, у каждой счётчик).

**Скорость движения** зависит от типа:

- A: Черновик → Проверка за один проход без остановок (~300 мс на переход), дальше — одна остановка: человек подтверждает результат (v4.10; автопринятие убрано). Если помощник попросил данные («Что именно не получается?», «Уточните, для кого услуга») — карточка в «Уточнении» с кнопками-вариантами и ждёт ответа, а не в «Проверке» (v4.13).
- B, C, D и обращения-проблемы: карточка **останавливается** на контрольных точках, на ней пульсирующий индикатор «Нужен ваш ответ». Ответить можно прямо в карточке или открыв задачу.

**Переполнение столбца:** когда в столбце 5 и больше карточек, они становятся компактными (тип, срочность, название, статус — детали в чате). В столбце видны 5 самых важных (ждут ответа / ошибка, затем по срочности) и кнопка **«Показать все · N»**. Она (или заголовок столбца) открывает столбец **на всю доску**: карточки плиткой слева направо, как файлы в проводнике (на 360 px — одной колонкой), под каждой — дата создания. **Сортировка:** сначала новые (по умолчанию) · сначала старые · по срочности · сначала ждут ответа; выбор запоминается. Назад — стрелка «←» или Esc.

**Ручное управление:** drag-and-drop; перетаскивание назад = «доработать», ИИ спрашивает, что изменить.

**Состояния карточки:** ожидает ИИ · ожидает пользователя · у специалиста · запланирована · ошибка (с кнопкой «Повторить»).

## 5. Разделы и контекст

- **«Общее»** — все задачи пользователя, любого типа. Новая задача всегда попадает сюда.
- **Разделы** — подборки задач из «Общего» **по смыслу**, а не отдельные доски. Их создаёт сам пользователь: название, описание «что сюда попадает», цветная метка из палитры. Разделы можно изменять и удалять — задачи при этом не удаляются.
- **ИИ раскладывает задачи** по названию и описанию разделов: новую — после разбора обращения; при создании или изменении раздела — все подходящие существующие (пачками, в фоне; в меню раздела есть «Разложить задачи заново»). Одна задача может быть в нескольких разделах или ни в одном.
- **Два вида разделов (v4.6):** при создании (и в «Изменить») — «Как пополняется»: **«По смыслу»** — ИИ раскладывает, как описано выше; **«Вручную»** (индивидуальный раздел) — человек сам выбирает обращения, не глядя на тематику («всё до отпуска», «для отчёта руководителю»); ИИ туда ничего не добавляет, «Разложить заново» в меню нет, в боковом меню — значок ладони («вручную» для скринридера). Созданный ручной раздел сразу открывает окно **«Добавить обращения»**: все обращения из «Общего» с галочками и поиском, отмечены уже входящие; «Готово · N» применяет. Кнопка «Добавить обращения» — в шапке любого раздела и в пустом разделе; пункт «Добавить обращения» — в «⋯» раздела. Отметки в меню обращения («Показывать в разделах») — `menuitemcheckbox`.
- **Ручное управление:** в меню карточки и задачи — «Показывать в разделах» (отметки) и «Убрать из «…»». Убранная задача остаётся в «Общем», и ИИ больше не добавляет её в этот раздел. Задача, созданная на доске раздела, сразу попадает и в «Общее», и в этот раздел.
- Доска раздела — те же 5 столбцов и тот же порядок карточек, что в «Общем», только отфильтрованные. На карточке — метки остальных разделов.
- Навигация: боковая панель на desktop (цветная метка, счётчик активных, «⋯» — изменить / разложить заново / удалить, «Новый раздел»), выдвижное меню на mobile.
- Без модели (демо-режим) раскладка идёт по совпадению основ слов с названием и описанием раздела.
- **Общий контекст раздела** (позже): после решения обращения ИИ формирует резюме (3–7 пунктов: что случилось, что помогло); при новом обращении подставляются релевантные резюме; экран «Что помнит этот раздел» с редактированием; в задаче — «Использован контекст из: …».

- **Цветовые схемы (v4.11).** Акцентные тона (крафт / терракота / ржавчина в таблице выше) задаёт схема — у каждого человека своя; нейтральные (крем, песок, камень, графит, чернила) общие.

  | Схема               | Светлый тон | Основной  | Глубокий  |
  | ------------------- | ----------- | --------- | --------- |
  | Терракота (default) | `#D4A27F`   | `#D97757` | `#B4552F` |
  | Шалфей              | `#B9C6BC`   | `#8FA394` | `#2E4A3B` |
  | Море                | `#A9C3D3`   | `#6E9BBA` | `#2F5F7F` |
  | Слива               | `#CFAFC5`   | `#B07D9F` | `#7A3F68` |
  | Охра                | `#DCC792`   | `#C9A24A` | `#80611B` |
  | Графит              | `#C4C4BF`   | `#9A9A95` | `#4A4A47` |

  Источник — `packages/tokens/src/palette.ts` (`colorSchemes`); темы строит тот же генератор (`buildLight` / `buildDark`), CSS — блоки `:root[data-scheme="…"]` только с отличающимися токенами. `npm run check -w packages/tokens` проверяет контраст всех схем в обеих темах (384 пары). Схема ставится атрибутом `data-scheme` на `<html>` до первой отрисовки (без «вспышки»), хранится в кабинете (`POST /api/auth/prefs { scheme }`, поле `scheme` у пользователя) и подтягивается при входе и при возврате во вкладку. - Верхняя граница столбцов — градиент готовности «теплеет»: камень → крафт → терракота (→ ржавчина в светлой теме).
- Под доской — «обои»: тёплый градиент и оригинальный контурный узор, включая маленьких летучих мышей.

### Общий характер

Спокойный, «бумажный», сдержанный: скругления 12–16 px (поле ввода — 20 px), тонкие границы, мягкие тени, много воздуха, минимум рамок и плашек; акцентный цвет — только для главного действия и «нужен ваш ответ». Анимации 200–400 мс.

### Типографика (v4.1)

- Интерфейс — **Onest**; заголовки экранов, приветствие, название обращения и **ответы помощника** — засечный **Source Serif 4** (кириллица, встроен в сайт): текст ИИ читается как текст, а не как интерфейс.
- Главная сотрудника (desktop): приветствие «Добрый день, Аня» крупным засечным, под ним большое поле «Опишите проблему» и примеры; список обращений слева — строками без рамок, «нужен ваш ответ» — точкой. Колонка чата — до 720 px.

## 9. Логотип

Знак — **летучая мышь, висящая вниз головой на перекладине** (как обращение висит на доске, пока его не решат); сложенные крылья делят тело на три полосы — столбцы доски. Рисунок оригинальный. Перекладина — терракота (`--logo-accent`), мышь — чернила / крем в тёмной теме (`--logo-primary`); складки и глаза — прозрачные вырезы. Используется только через `<Logo variant="full" | "mark" tone="color" | "mono" />`; надпись — «Канбат». Favicon и PWA-иконки генерируются из той же геометрии.

- **Подпись авторов (v4.5):** «Канбат made by [знак] Code Invaders» — как «Claude made by Anthropic»: мелко и неярко (`text-xs`, `text-fg-muted`) внизу бокового меню (под «Темой») и внизу экрана входа. Знак команды — векторизованный логотип Code Invaders (голова с антеннами), один цвет `currentColor`, 16 px; компоненты `<TeamMark />` и `<MadeBy />` (`src/brand`), исходник — `docs/brand/code-invaders.png`. Логотип продукта по-прежнему только через `<Logo />`.
- **«ИИ думает»:** знак оживает — мышь (лапки и тело) покачивается на неподвижной перекладине, как от ветра (≈2,6 с, неравномерная амплитуда); у трудных задач тело ещё и «дышит» (лёгкое расширение). Используется в чате («Помощник думает…», под пишущимся ответом), на карточке и в списке обращений. При `prefers-reduced-motion` — неподвижна.

## 10. Системный промпт (база для промптов по шагам)

```
Ты — ИИ-помощник техподдержки. Каждое обращение пользователя — карточка на канбан-доске
(Черновик → Уточнение → В работе → Проверка → Готово).

1. Разбери обращение: суть проблемы, затронутый сервис или область, известные факты,
   чего не хватает для решения, срочность (critical / high / normal / low) и режим:
   answer — это вопрос, на который можно ответить текстом;
   steps — пользователь может решить проблему сам по шагам;
   escalate — без специалиста не решить (права администратора, ремонт, доступы и т. п.).
   Верни JSON и больше ничего.

2. Вопросы: задавай только то, без чего нельзя решить ЭТУ проблему; не переспрашивай
   известное; не больше 3 за раз; у каждого 2–4 варианта и «на твоё усмотрение».
   Если обращение срочное — спрашивай только критичное или не спрашивай вовсе.

3. Решение: последовательность действий, по одному действию на шаг, простым языком
   без жаргона. Для срочных — сначала самый быстрый обходной путь.
   Если сценарий не помог — предложи другой подход; если решения нет — передай специалисту.

4. Передача специалисту: сводка — исходное обращение, вопросы и ответы, предполагаемая
   проблема, уже выполненные действия, текущий результат, другая важная информация.
   Пользователь не должен заново описывать ситуацию.

Отвечай на языке пользователя, по существу, без лишних вступлений.
```

## 11. Технические рекомендации

- **Frontend:** React + TypeScript, Tailwind (только токены), dnd-kit, Motion, PWA.
- **Backend:** NestJS; хранилище за интерфейсом `Storage` — сейчас JSON-файл (`FileStorage`, без установки БД), на сервере в интернете — PostgreSQL (+pgvector) с тем же интерфейсом; Redis + BullMQ для отложенных задач; SSE для стриминга.
- **LLM:** провайдер выбирается переменными окружения сервера, код клиента не меняется. Structured outputs по JSON-схемам, стриминг; без модели — демо-режим.
  1. `LLM_PROVIDER=ollama` (по умолчанию): Ollama на этом компьютере или на другом — `OLLAMA_URL=http://<адрес>:11434` (там `OLLAMA_HOST=0.0.0.0`); `qwen2.5:7b` / `qwen3:8b`.
  2. `LLM_PROVIDER=openai`: любой сервис с OpenAI-совместимым API — `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` (OpenAI, OpenRouter, Groq, vLLM, LM Studio и т. п.). JSON-схемы через `response_format: json_schema` (если сервис не умеет — `json_object` со схемой в промпте), стриминг через SSE. ✅
- **Надёжность ИИ (v4.4.1):** Ollama отвечает на запросы по очереди, поэтому один «залипший» запрос задерживает все обращения. Поэтому: предел длины ответа (`num_predict` / `max_tokens`: JSON — 2048, ответ — 2048, выполнение плана — 4096 токенов); модель должна начать отвечать за `LLM_TIMEOUT_S` (по умолчанию 120 с, включая загрузку в память), JSON целиком — за 1,5×, пауза посреди ответа — не дольше 60 с; иначе — понятная ошибка и «Повторить». Браузер ушёл (новое сообщение, «Стоп», закрыта вкладка) — запрос к модели отменяется (перехватчик `AbortOnCloseInterceptor` + `AsyncLocalStorage`). В потоке SSE раз в 10 с — комментарий-«пульс» (туннели не рвут молчащее соединение). После перезагрузки страницы обращение, ответ на которое писался, показывает «Ответ прервался — Повторить», а не «думает» вечно. `POST /api/llm/check` — проверка скорости: время до первого слова и всего, где работает модель (`/api/ps`: видеокарта / частично / процессор), сколько запросов выполнялось одновременно.
- **Переходы (v4.9, заменяет v4.6.1):** `layout/AppHistory.tsx` подменяет navigator роутера: переход внутри Канбата **заменяет** запись браузера (одна запись на весь Канбат); исключение — узкий экран (< 1024 px): открытие подробностей (адрес с `/t/`) добавляет одну запись с пометкой, закрытие — `history.go(-1)` и, если нужно, замена на нужный экран; жест «Назад» на телефоне закрывает подробности. ## 13. Режим поддержки (кейс «Поддержка, которая не бесит»)

1. **Обращение** — свободный текст, без категорий и терминологии.
2. **Разбор («Что произошло»)** — ИИ опирается **только на текст пользователя** и ничего не додумывает. Если обращения пока нет («F», «тест», «привет», «ничего не случилось»), задача не придумывается: карточка встаёт в «Уточнение», а помощник **отвечает по-человечески на последнюю реплику** (ответ пишет модель с учётом переписки, не повторяясь: поздоровается, порадуется, что всё в порядке, спросит, не случайно ли ушло сообщение). Есть кнопка «Закрыть обращение» — если помощь не нужна. Любой вопрос или просьба, даже не рабочие («как установить майнкрафт») и даже простые без «?» («Сколько будет 2 + 3», «7*6»), — это обращение; помощник не здоровается, если человек не здоровался; реплики без сути при разборе пропускаются. Иначе ИИ определяет суть, сервис/область, известные обстоятельства, чего не хватает, **срочность** и режим (answer / steps / escalate). В чате — карточка разбора, на доске — бейдж срочности.
3. **Уточняющие вопросы** — только по недостающей информации и только если от ответа зависит совет (0–2, срочно — 1). Принцип: пользователь не отвечает на вопросы, не нужные для его проблемы. Вопросы — в панели внизу (v4.14): варианты, «Свой ответ», «Пропустить вопрос», «Ответить без уточнений».
4. **Решение по шагам** — по одному шагу. У каждого шага — короткий вопрос о результате и два ответа **по смыслу этого вопроса** (их формулирует модель): «Почта открылась в браузере?» → «Да, открылась» / «Нет, не открывается»; нейтральные «Получилось / Не получилось» — только запасной вариант. Ответ «да» — следующий шаг, «нет» — другой сценарий. Можно ответить своими словами; «Позвать специалиста» — всегда под рукой. Эти же формулировки попадают в историю и в сводку для специалиста.
5. **Проверка результата** — для проблемы по шагам: «Проблема решена?» Если нет — новый сценарий (другой подход); после двух неудачных сценариев — передача специалисту. Для вопроса и заявки — кнопки по смыслу ответа (п. 3).

**Единая инструкция помощника (v4.13).** Одна базовая инструкция для всех этапов, говорящих с человеком (`apps/api/src/org/profile.ts → buildBase`): кто помощник и с чем помогает, обращение и тон, «опираешься только на слова человека», «не отвечаешь наполовину — сначала спросишь недостающее», «не просишь пароли, коды из SMS и данные карт», «если самому не решить — предложишь специалиста», «не пишешь служебного». Этапы добавляют только задачу: «СЕЙЧАС — РАЗБОР…», «…— УТОЧНЕНИЕ…», «…— РЕШЕНИЕ ПО ШАГАМ…», «…— ОТВЕТ ПО СУЩЕСТВУ…». Роль по умолчанию — универсальный помощник поддержки («Канбат»: любые вопросы и проблемы); профиль организации подставляет свою роль, темы, «вы/ты», тон и правила «Всегда / Никогда». Служебные запросы (сводка специалисту, оценка ответа, раскладка по разделам, БатФорум) — отдельные, с человеком не говорят.

**Режимы разбора (v4.13):** «ответ» (вопрос — ответить текстом), **«заявка»** (записаться, оформить, заказать, вернуть, получить документ — собрать данные и объяснить порядок; оформление с подтверждением — п. 17, «Действия»), «шаги» (проблема, которую человек решит сам), «специалист». Срочность — только по тому, насколько горит и сколько людей затронуто (вопрос тоже бывает срочным). «Размыто» без вопросов не бывает: сервер добавляет общие уточнения. Вариант «Не знаю» — только там, где человек правда может не знать. Запасные уточнения сервера — без привязки к ИТ. 6. **Передача специалисту** — кнопка доступна всегда; для режима escalate — автоматически. Сводка: исходное обращение, вопросы и ответы, предполагаемая проблема, выполненные действия, текущий результат, другая важная информация. Статус карточки «У специалиста». 7. **Срочные обращения** (critical: работа заблокирована прямо сейчас или дедлайн в ближайший час) — без лишних вопросов, первым шагом — самый быстрый обходной путь; «Позвать специалиста» на виду.

7a. **Когда ИИ отвечает долго (v4.4.1):** под «Помощник думает…» через 8 с появляется время ожидания, через 25 с — объяснение («модель может загружаться, работать на процессоре или быть занятой другим запросом») и кнопки **«Передать специалисту»** (сразу, со сводкой из переписки с пометкой «ИИ отвечал слишком долго») и **«Остановить»**; подсказка про «Проверить скорость ИИ» в «Настройках». Реплика без сути в решённом или проверяемом обращении («Добрый вечер», «спасибо», «ответьте», «вы тут?») — короткий живой ответ, карточка остаётся на месте; сообщения пользователя показываются как есть, без приставок. 8. **Когда ИИ недоступен** (нет модели, сервер ИИ не отвечает): вверху — «ИИ-помощник сейчас недоступен. Обращения принимаются…». На обращение помощник **не притворяется ИИ**: говорит, что ИИ недоступен, и предлагает похожие **частые вопросы** (8 тем: пароль, почта, VPN, принтер, доступы, интернет, тормозит компьютер, камера/микрофон) с готовыми инструкциями и «Помогло?», плюс «Передать специалисту». «Не помогло» → передача; сводка специалисту — только из переписки, с пометкой «ИИ был недоступен». Новое сообщение подбирает вопросы заново (или запускает обычный разбор, если ИИ вернулся). Ответы-заготовки вместо модели — только в демо-режиме сервера (`LLM_DEMO=1`, для разработки).

**Тестовые сценарии:** простое (решается самостоятельно) · неоднозначное (нужны уточнения) · несколько симптомов · не решается самостоятельно (передача) · срочное (важна скорость).

## 14. Контр-фича: пульт поддержки (доска специалиста)

Сотрудник спрашивает ИИ, специалист **принимает заявки**. Поэтому у специалиста своё рабочее место — **«Пульт поддержки»** (`/support`), а не экран сотрудника.

- **Меню специалиста** (вместо личных разделов): «Пульт поддержки» — очереди **Все заявки · Новые · Мои · В работе · Ждут пользователя · Решённые** (у каждой — число открытых заявок, у «Новых» — яркий счётчик), ниже «Сообщество» — БатФорум (специалисты его модерируют). Личной доски, разделов, «Нового раздела», своих обращений и вида «Список / Доска» сотрудника у специалиста **нет**: после входа сразу открывается пульт, адреса `/s/*` ведут на пульт. Если у специалиста самого проблема — он входит как сотрудник (без кода).
- **Два режима** (переключатель «Доска / Чат» в шапке, выбор запоминается; по умолчанию — «Доска»):
  - **Доска** — главный канбан продукта: столбцы **Новые → В работе → Ждёт пользователя → Решено**. Очередь «Мои» — три столбца (новых среди взятых нет), очередь одного статуса — один столбец во всю ширину плиткой. Карточка открывает заявку панелью справа (на телефоне — поверх).
  - **Чат** — как в мессенджере: слева заявки очереди (аватар-буква, имя, заголовок, «ждёт N мин» / «ответили … назад», срочность, «взял: …»; группы «Ждут ответа» · «Ждут пользователя» · «Решённые» свёрнуты), справа — заявка; без выбранной — «Выберите заявку слева». Новое сообщение — плавная прокрутка к нему.
- **Заявка:** заголовок, срочность, статус, «передано … назад», «от кого», «взял: …», причина передачи; **сводка из 6 пунктов** (п. 13.6) с «Скопировать сводку» (для внешней тикет-системы) и пометкой «Разговор сотрудника с ИИ остаётся у него — здесь только сводка»; **«Переписка с сотрудником»** — только сообщения после передачи и ответы специалистов пузырями со временем; действия — «Взять в работу», «Отметить решённым», ответ сотруднику (Ctrl+Enter; приходит в его чат, заявка переходит в «Ждут пользователя», у сотрудника карточка — в «Проверку»). «Отметить решённым» — у сотрудника карточка тоже идёт в «Проверку» с вопросом «Специалист отметил обращение решённым. Проверьте: проблема ушла?»; в «Готово» — после «Решено», «Не помогло» возвращает заявку специалисту (v4.10).
- **Приватность:** разговор сотрудника с ИИ до передачи специалисту **не показывается и на сервер в заявку не отправляется** — только сводка, статус и сообщения после передачи (правило `messagesForSpecialist`: сообщения человека, написанные после передачи, без ответов на кнопки). Сервер повторяет ту же фильтрацию и очищает старые заявки. Нужны детали — специалист спрашивает в ответе.
- Сортировка **«Сначала срочные» / «Дольше ждут»** (запоминается), **подсветка давно ждущих** (дольше 15 минут без ответа), в шапке — сводка «Ждут ответа: N · срочных: M · дольше 15 мин: K».
- **Доступ:** пульт — только для специалистов поддержки: вход с ролью «Специалист» и кодом доступа (п. 15). Специалист видит заявки **всех** сотрудников; ответы и статусы доходят до сотрудника за несколько секунд. Сотруднику `/support` показывает «Доступ только для специалистов». Настройки специалиста — только аккаунт.
- Ценность: специалист сразу видит, что случилось, насколько срочно и что уже пробовали, — пользователь не пересказывает ситуацию, а его переписка с ИИ остаётся личной.

## 15. Доступ для других и развёртывание

- **Вход в личный кабинет (v4.6):** имя + пароль; роль «Сотрудник» или «Специалист» (у специалиста ещё общий код доступа — `SUPPORT_CODE`, иначе сервер придумывает код и показывает при запуске; с кодом администратора `ADMIN_CODE` специалист входит как администратор организации — п. 17.1). Имя без учёта регистра и лишних пробелов; кабинеты сотрудника и специалиста с одинаковым именем — разные. При вводе имени экран подсказывает: «Новый личный кабинет — придумайте пароль» (кнопка «Создать кабинет»), «С возвращением! Введите пароль» или «Этому кабинету ещё не задан пароль — придумайте его сейчас» (кабинеты до v4.6: данные сохраняются) — `POST /api/auth/check`. Пароль — не короче 6 символов, «Показать пароль»; хранится только scrypt-хэш с солью, клиенту не отдаётся. Перебор ограничен: 10 неверных паролей с адреса или по кабинету за 10 минут → вход закрыт на 10 минут (429). «Настройки» → «Аккаунт» → «Сменить пароль» (нужен текущий; остальные устройства выходят из кабинета). Восстановления пароля нет (демо); в рабочей версии — корпоративный вход (SSO). Выход — в меню. Весь API, кроме входа, проверки имени и статуса ИИ, — только для вошедших (токен в заголовке `Authorization`).
- **Пустой кабинет (v4.6):** новый человек видит только своё: «Общее» без обращений, приветствие по имени и «Это ваш личный кабинет… Показать примеры». Примеры добавляются к своим обращениям, ничего не удаляя (у каждой порции примеров свои id); в «Настройках» — «Добавить примеры обращений». Разрушительное «Вернуть демо-данные» убрано.
- **Данные на сервере:** доска каждого сотрудника (у специалиста доски нет) (задачи, переписка, разделы, настройки) сохраняется на сервер через ~0,8 с после изменения; в меню — «сохраняю… / нет связи, повторю / не сохранено: причина». Новый пользователь получает пустой кабинет (примеры — по кнопке).
- **Несколько окон и устройств (v4.5):** каждое сохранение идёт поверх известной версии (`baseRev`); если доску тем временем сохранило другое окно — сервер отвечает 409 со своей версией, клиент сливает без потерь (задачи — объединение, при расхождении — более свежая по `updatedAt`; переписка — объединение по id; порядок — свой, затем новые; разделы — объединение) и сохраняет. Удаление помнится метками удаления (`tombstones`, последние 300) — удалённое не возвращается из «старого» окна. При возврате в окно (фокус) — подтягиваются изменения из других окон; без лишних сохранений, если отличий нет.
- **Безопасность входа (v4.5):** код специалиста защищён от перебора — 5 неверных попыток с одного адреса или 30 со всех за 10 минут закрывают вход специалиста на 10 минут (429). Сервер отдаёт `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy`. Ошибки «по существу» (например, доска больше 5 МБ) не повторяются бесконечно — «не сохранено: причина».
- **Обращения к специалисту (`Ticket`):** при передаче сотрудник отправляет на сервер сводку и статус, дальше — только свои сообщения после передачи (разговор с ИИ остаётся на его доске, п. 14). Специалист отвечает и меняет статус на сервере; сотрудник забирает ответы и статусы опросом раз в ~4 с (в фоне — реже). Кто новее — решает ревизия статуса (`escalation.rev`), при равной — сервер.
- **Ссылка для всех (сейчас):** `npm run share` — сборка, сервер на одном порту и туннель. Порядок: **Tuna** (tuna.am, российский сервис; установка и `tuna login` один раз; бесплатно — сеансы по 30 минут) → Cloudflare quick tunnel (с июня 2025 российские провайдеры ограничивают Cloudflare до 16 КБ — в России даёт Error 1033 / пустую страницу) → localhost.run через ssh. Ссылка печатается, только если сервер сам её открыл; иначе — адреса в локальной Wi-Fi сети. Работает, пока включён компьютер; ссылка меняется при каждом запуске.
- **Сервер в интернете (v4.8):** `deploy/README.md` — пошагово для Windows. ## 16. БатФорум (v4.2, раскладка — v4.3, модерация и сообщества — v4.7)

Похожие проблемы и ответы коллег — часто решение уже есть и обращение не нужно (меньше нагрузки на поддержку). Название — **«БатФорум»**; пункт «БатФорум» в меню («Сообщество»).

- **Сообщества** (общие для компании; стартовые — ниже, новые создают специалисты и предлагают сотрудники — п. 16.1), адреса в духе Reddit: б/почта (Почта и календарь) · б/доступы (Доступы и пароли) · б/сеть (Сеть и VPN) · б/железо (Оборудование) · б/программы (Программы) · б/разное (Другое); б/все — весь БатФорум.
- **Раскладка (как Reddit), desktop ≥ 1280 px — три колонки:**
  - **слева** — «О сообществе» (для б/все — «О БатФоруме»): иконка и полоса-баннер, название, б/адрес, описание, статистика (тем · решено · участников; для б/все — тем · решено · ждут ответа), последняя активность, кнопка «Создать тему», правила (4 пункта), модераторы (специалисты поддержки);
  - **по центру** — строка поиска («Искать на БатФоруме» / «Искать в б/…») и лента. **Без запроса** — «Рекомендации» (в сообществе — «Лучшее в сообществе») и сортировки: **Для вас / Лучшее** · Новое · Топ · Без ответа. **С запросом** — «Результаты по «…»», число тем, где искали (во всех сообществах / в б/…) и кнопка «Искать везде»; ничего не нашлось — «Создать тему «…»»;
  - **справа за вертикальной чертой** — «Сообщества»: б/все («Рекомендации») и каждое сообщество с названием и числом тем, текущее выделено.
  - 1024–1279 px: левая колонка сворачивается в компактную шапку над лентой; < 1024 px (и 360 px) — сообщества лентой чипов сверху, шапка сообщества с кнопкой «+», сортировки без иконок, без горизонтальной прокрутки страницы.
  - _Отличие от Reddit:_ у Reddit список сообществ слева, а «о сообществе» справа; здесь сделано зеркально, по запросу. Поменять местами — одна правка в `ForumLayout`.
- **Карточка темы в ленте (пост):** колонка «Полезно» (один голос, без минусов) слева; мета — иконка и б/сообщество, автор (пометка «Специалист»), время, «Закреплено»; чип **«Похоже на ваше обращение «…»»** для персональных рекомендаций; заголовок (засечный шрифт) — ссылка на тему; превью текста (3 строки); подвал — число ответов, «Есть решение», «Поделиться» (копирует ссылку), «из решённого обращения».
- **Рекомендации «Для вас»:** «горячесть» = (Полезно + 3·решение + 0,5·ответы + 1) / (часы с создания + 2)^0,5; если тема похожа на одну из последних 20 задач пользователя (уверенное совпадение слов) — поднимается выше и получает чип с названием этой задачи; закреплённые — первыми. Стартовая доска нового пользователя сразу сохраняется на сервере, чтобы рекомендации работали с первого входа.
- **Тема:** «← б/…», пост (мета, меню «Закрепить / Удалить», заголовок, текст в Markdown, подвал), поле ответа над ответами (Ctrl+Enter), «Ответы · N» — аватар-буква и линия-«нить», **решение первым**, дальше по «Помогло». Левая и правая колонки — те же, что у сообщества темы.
- **Кто что может:** писать темы и отвечать — все; отметить решение — автор темы или специалист; закрепить, перенести, закрыть — специалист; изменить заголовок, удалить тему или ответ — автор или специалист; пожаловаться — остальные (п. 16.3). Удаление аккаунта удаляет и его сообщения на БатФоруме.
- **Связь с обращениями:** при наборе обращения — «Похожие обсуждения на БатФоруме» (до 3, только уверенные совпадения, стоп-слова отбрасываются); в режиме без ИИ — рядом с частыми вопросами; у решённого обращения — **«Поделиться решением на БатФоруме»**: ИИ готовит черновик (вопрос + «Проблема / Что помогло», без имён, телефонов, почт, логинов, IP), человек проверяет и публикует; без ИИ — черновик из переписки.
- Стартовые обсуждения (7 тем) создаются один раз при первом запуске. API: `/api/forum/*` (сортировки `best | new | top | unanswered`), `POST /api/llm/forum-draft`; хранение — в том же хранилище (`Storage`), при переезде — таблицы PostgreSQL.

### 16.1. Сообщества (v4.7)

- **Хранятся в данных** (`Storage`: `ForumCommunity` — адрес, название, описание, значок, статус `active | proposed | rejected | archived`). Шесть стартовых создаются при первом запуске; «Другое» (б/разное) всегда последним и не архивируется — сюда переезжают темы.
- **Специалист** создаёт сообщество сразу (кнопка «+» над списком сообществ / чип «Сообщество» на телефоне), меняет название, адрес, описание, значок («⋯» в карточке сообщества) и убирает в архив (окно объясняет, сколько тем переедет в б/разное; в каждой теме — запись в журнале).
- **Сотрудник** предлагает («Предложить сообщество»): предложение попадает специалистам в «На проверке», автор видит «Мои предложения» со статусом (ждёт / одобрено / отклонено: причина). Не больше 3 ждущих предложений от человека.
- **Форма:** название (3–40), адрес «б/…» собирается из названия (буквы, цифры, дефис; 2–24), описание (10–140), значок из готового набора (18 штук, цвета — токены темы). Повтор адреса или названия среди действующих и ждущих — понятная ошибка; адреса «все» и служебные заняты. Всего активных — до 24.
- Специалист при одобрении может поправить поля; при отказе — написать причину (увидит автор).

### 16.2. Порядок в темах (v4.7)

- **Фильтр мусора на сервере** (заголовок, подробности, ответы, названия сообществ): один символ 5+ раз подряд, меньше половины букв, «слова» из 5+ русских букв без гласных; заголовок — хотя бы два слова. Ошибка объясняет, что поправить. Нормальные вопросы («VPN не подключается», «1С тормозит по утрам») проходят.
- **Лимиты частоты:** 3 новые темы за 10 минут, 10 ответов за 5 минут, 20 жалоб в час; специалистов не ограничивают; 429 с понятным «попробуйте через N мин».
- **Подсказка сообщества** в окне «Новая тема»: через ~1,2 с после паузы в наборе — «Похоже, это про б/… · Выбрать» (с пометкой «подсказка ИИ» или «по совпадению слов»), и «Не похоже на вопрос — напишите, что случилось». Ничего не блокирует. Без ИИ — совпадение слов с названием, описанием и темами сообщества (`POST /api/llm/forum-suggest`).

### 16.3. Модерация и жалобы (v4.7)

- **Меню «⋯» у темы** (в ленте и в теме): специалист — закрепить, перенести в…, закрыть/открыть для ответов, снять жалобы, изменить заголовок, удалить; автор — изменить заголовок, удалить; остальные — «Пожаловаться».
- **Закрытая тема:** сотрудники не отвечают (вместо поля — «Тема закрыта для ответов»), специалист может ответить.
- **Журнал модерации** в теме: «Ольга (специалист) перенёс из б/почта в б/доступы · 2 ч назад»; правка заголовка автором в журнал не пишется.
- **Жалоба:** причина (спам или бессмыслица · не в том сообществе · личные данные · грубость · другое — с обязательным пояснением), одна от человека; на свою тему и специалисту — нельзя. **После 3 жалоб тема скрыта** из ленты, поиска и счётчиков до решения специалиста; автор и специалисты её видят с пояснением.
- **«На проверке»** (`/forum/review`, только специалисты; пункт меню со счётчиком «жалобы + предложения», обновляется раз в 20 с): темы с жалобами (причины, пояснения, кнопки «Оставить», «Перенести», «Закрыть», «Удалить») и предложенные сообщества («Одобрить» с правкой, «Отклонить» с причиной). Любое решение специалиста по теме (перенос, закрытие, правка, «Оставить») снимает жалобы.
- API: `POST /api/forum/sections` (создать/предложить), `POST /api/forum/sections/:id` (изменить), `…/:id/archive`, `GET /api/forum/proposals`, `POST /api/forum/proposals/:id/approve|reject`, `POST /api/forum/threads/:id/move|lock|title|report|reports/dismiss`, `GET /api/forum/review`, `GET /api/forum/review/count`.

## 17. Профиль организации (следующий этап, решения от 28.09)

Канбат — предложение на рынок: каждая организация подстраивает помощника под себя. **Одна организация — один сервер** (свой `deploy/install.sh`, данные не смешиваются); общий облачный сервис для многих организаций — позже.

В первую версию входят все четыре части; настраивает администратор организации:

1. **Характер и правила разбора:** имя и тон помощника, запреты и обязательные фразы; свои услуги/сервисы, что срочно, что всегда трудное или сразу к специалисту — правила важнее мнения модели (сложность предсказуема).
2. **Действия:** организация описывает действие («Записаться на приём» — поля, куда отправить); помощник по разговору заполняет форму, **человек подтверждает**, и только тогда она уходит — во внутреннюю очередь (талон в пульте) и/или на webhook организации; статус («Талон №…, окно…») виден в карточке. Без подтверждения ИИ ничего не отправляет.
3. **База знаний:** инструкции и частые вопросы организации; ответы — со ссылкой на источник (pgvector, «память»).
4. **Шаблоны отраслей:** «ИТ-поддержка компании», «Центр госуслуг», «Игровая платформа», «Интернет-магазин» — готовые тон, правила и действия; без чужих брендов и товарных знаков.

Работа по шагам (решения 28.09): 1) роль, тон, тонкости, шаблоны, администратор — ✅ v4.12; единая инструкция и этапы по смыслу — ✅ v4.13; 2) правила разбора и **жёсткие правила** (выполняет сервер: слова-триггеры → срочно / к специалисту, запрещённое в ответе — не показывать); 3) **образцы ответов** и **проверочные вопросы** с прогоном на настоящей модели; 4) **разбор ошибок** — ответы с «Не помогло» и «Доработать» (с согласия сотрудника, только этот обмен репликами) превращаются в правило, образец или проверочный вопрос; 5) действия (талоны и заявки с подтверждением); 6) база знаний (сначала поиск по словам, pgvector — при переезде на PostgreSQL). Администратору **не отдаём**: текст базовой инструкции целиком (сломает формат), отключение защит («Готово» — только после подтверждения, отправка — только после «Подтвердить»), дообучение модели.

### 17.1. Шаг 1 — роль и характер помощника (v4.12) ✅

- **Администратор организации** — специалист, который при входе ввёл **код администратора** (`ADMIN_CODE` в `.env`; нет — сервер придумывает 8 цифр и печатает при запуске рядом с кодом специалиста; `deploy/install.sh` спрашивает его отдельно и не даёт совпасть с кодом специалиста). Права — по коду последнего входа: тот же человек с кодом специалиста — обычный специалист. В меню пульта — раздел «Администратор» → «Организация» (`/org`); остальным — «Доступ только для администратора организации», API — 403.
- **Экран «Организация»:** «Шаблон отрасли» (5 вариантов, заполняет поля, название организации и фраза в конце сохраняются), «Помощник» (название организации — необязательно; имя; роль — кто помощник и для кого; с чем помогает — темы для «что ты умеешь»; обращение; тон; вопросы не по теме), «Тонкости» («Всегда», «Никогда» — до 10 правил по 200 символов, добавить / удалить; фраза в конце каждого ответа — не вопрос, иначе карточка ждала бы ответа), «Проверить на вопросе» (пробный ответ по черновику, с примерами вопросов под шаблон; на доску не попадает). Внизу закреплено: состояние («Есть несохранённые изменения» / «Сохранено 28 сентября, 14:05 · имя»), «Отменить изменения», «Сохранить».
- **Как действует:** пока профиль не сохранён — роль по умолчанию (универсальный помощник поддержки, v4.13). После сохранения роль, темы, обращение, тон и правила «Всегда / Никогда» подставляются в **единую базовую инструкцию** (п. 13, v4.13) — для разбора, уточнения, шагов, ответа и разговора без обращения; правила «уточняй…» учитываются уже на разборе. Фразу в конце добавляет сервер после ответа модели — она не теряется и не переиначивается. Раскладка по разделам, БатФорум, сводка для специалиста и оценка ответа — служебные, без правил организации.
- **API:** `GET /api/org` (всем — `info`: настроен ли, названия; администратору — профиль, шаблоны, пределы), `PUT /api/org` (администратор), `POST /api/llm/org-preview` (администратор). Хранение — служебные данные (`orgProfile`), без новой базы.
