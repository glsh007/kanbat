# Канбат (Kanbat)

Канбан + bat: обращения «висят» на доске, как летучая мышь на перекладине, пока их не решат.
ИИ-помощник техподдержки, в котором каждое обращение — карточка на канбан-доске:
Черновик → Уточнение → В работе → Проверка → Готово. Сделан под кейс хакатона
«Поддержка, которая не бесит»: помощник разбирает обращение («что произошло, насколько срочно,
что делать»), задаёт только нужные вопросы, ведёт по шагам и при необходимости передаёт
специалисту готовую сводку.

**Как устроено (ТЗ v4.5):** сотрудник просто пишет и видит путь своей заявки — экран «Мои обращения»
(список + чат, полоска из 5 этапов); поддержка работает на своём пульте (канбан или чат) и получает готовую
сводку. Канбан-доска у сотрудника — необязательный вид «Доска» (переключатель в шапке).

ТЗ — `docs/TZ.md` (копия из проекта Claude «Хакатон сентябрь»).

## Структура

```
apps/
  web/          React + TypeScript + Vite + Tailwind v4 + Motion
  api/          NestJS: вход (/api/auth), доски (/api/board), обращения (/api/support),
                ИИ (/api/llm/* — Ollama или OpenAI-совместимый сервис), хранилище (src/store)
scripts/        start.mjs — сайт + API одним сервером; share.mjs — ссылка для всех через Cloudflare
packages/
  tokens/       палитра, темы, генерация tokens.css, проверка контраста
  shared/       доменные типы: столбцы, типы задач A–D, Task, Section…
```

## Запуск

Нужны Node.js 20.19+ (рекомендуется 22) и [Ollama](https://ollama.com) с моделью, например:

```bash
ollama pull qwen2.5:7b      # или qwen3:8b
```

```bash
npm install
npm run dev          # сайт http://localhost:5173 + сервер http://localhost:3000 одной командой
```

Без Ollama приложение честно пишет «ИИ сейчас недоступен» и работает как классический бот: частые вопросы
с готовыми инструкциями и передача специалисту. Ответы-заготовки вместо модели — только для разработки:
`LLM_DEMO=1` в `apps/api/.env`.

При первом открытии — вкладка «Регистрация»: как к вам обращаться, ник (латиница, цифры и «_»; по нему вы
входите), роль и пароль (не короче 6 символов) дважды. Затем Канбат покажет **фразу из 6 слов** —
сохраните её: по нику и фразе можно задать новый пароль («Забыли пароль?» на экране входа). Потом вход — по нику и паролю. Кабинеты,
созданные до v4.17, входят по имени, как раньше, и выбирают ник в «Настройках». Кабинет видит только его хозяин. Для входа специалистом
нужен ещё код — он напечатан в окне запуска («Код входа для специалистов»). Код администратора организации
(«Код администратора организации» там же) открывает «Организация» — роль, тон и правила помощника. Новый кабинет пустой —
примеры по кнопке «Показать примеры». Данные — в `apps/api/data/kanbat.json` (пароли — только хэши).

## Открыть Канбат другим людям (пока работает этот компьютер)

В России надёжнее всего российский сервис туннелей **Tuna** — один раз установить и войти:

```bash
winget install --id yuccastream.tuna
# закрыть и открыть cmd заново
tuna login
```

Дальше каждый раз:

```bash
npm run share
```

Команда соберёт Канбат, запустит его, откроет туннель, **сама проверит ссылку** и только тогда напечатает её
(`https://….tuna.am`). Бесплатный сеанс Tuna — до 30 минут, потом запустите команду снова (ссылка новая).
Если Tuna не установлен — пробуются Cloudflare (в России с июня 2025 провайдеры его ограничивают: Error 1033)
и localhost.run (`ssh`). Если ни один не открылся — печатаются адреса для той же Wi-Fi сети.
Выбрать вручную: `npm run share -- --via tuna|cloudflare|ssh`, без пересборки — `--no-build`.

## Сервер в интернете (не зависит от вашего компьютера)

Пошаговая инструкция для Windows — **[deploy/README.md](deploy/README.md)**. Коротко: VPS с Ubuntu, домен (A-запись на IP),
ключ Yandex AI Studio, затем на сервере:

```bash
unzip -o kanbat.zip && cd kanbat && bash deploy/install.sh
```

Скрипт ставит Docker (с зеркалами Docker Hub для России), спрашивает домен, каталог и ключ ИИ, собирает и запускает
Канбат за Caddy с автоматическим HTTPS, проверяет ИИ (`scripts/check-ai.mjs`) и включает ежедневную копию данных.
Обновление — `deploy/update.sh`, копия — `deploy/backup.sh`. ИИ по умолчанию — **Qwen в Yandex AI Studio**
(`LLM_PROVIDER=yandex`, `YANDEX_FOLDER_ID`, `LLM_API_KEY`, `LLM_MODEL=qwen3.6-35b-a3b`);
любой другой OpenAI-совместимый сервис — `LLM_PROVIDER=openai`; своя Ollama (закрытый контур) — сервис `ollama`
в `docker-compose.yml`. Хранилище спрятано за интерфейсом `Storage` (`apps/api/src/store`): для большой команды
добавляется PostgreSQL-реализация, остальной код не меняется.

Полезные команды:

```bash
npm run check:contrast   # проверка WCAG AA для обеих тем (падает, если пара не проходит)
npm run tokens           # пересобрать packages/tokens/tokens.css из themes.ts
npm run typecheck
npm run lint
npm run build
npm run icons -w @app/web   # пересобрать favicon и PWA-иконки
```

Страница `/design` — витрина дизайн-системы для команды (в меню её нет): палитра, токены, компоненты, контраст.

Переполненный столбец (5+ карточек): компактные карточки, видны 5 самых важных; «Показать все · N» (или заголовок)
открывает столбец на всю доску плиткой, как файлы в проводнике. Сортировка: сначала новые (по умолчанию), старые,
по срочности, ждут ответа — запоминается. Назад — «←» или Esc.

Обращения пока нет («F», «привет», «ничего не случилось») — задача не выдумывается: помощник отвечает по-человечески
на последнюю реплику и ждёт, что человек расскажет; «Закрыть обращение» — если помощь не нужна.

### ИИ не только на этом компьютере

Ollama может работать на другом компьютере — на нём задайте `OLLAMA_HOST=0.0.0.0`, а здесь в `apps/api/.env` —
`OLLAMA_URL=http://<адрес>:11434`. Облачный Qwen и на вашем компьютере: в `apps/api/.env` те же `LLM_PROVIDER=yandex`,
`YANDEX_FOLDER_ID`, `LLM_API_KEY`; проверка — `npm run check-ai`.

## Режим поддержки (кейс, ТЗ v2 п. 13)

| Пункт кейса                    | Где в продукте                                                                                                                                                                                                                                 |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Обращение свободным текстом | «+ Новое обращение» в Черновике (есть 5 примеров под тестовые сценарии)                                                                                                                                                                        |
| 2. Понимание проблемы          | Карточка «Что произошло» в чате: суть, сервис, известные факты, чего не хватает, срочность; бейдж срочности на доске                                                                                                                           |
| 3. Уточняющие вопросы          | Только по недостающему (0–3, срочное — максимум 1), варианты ответа в один клик                                                                                                                                                                |
| 4. Решение                     | Шаги по одному; после шага — вопрос о результате и ответы по смыслу («Значок VPN зелёный?» → «Да, зелёный» / «Нет, серый»)                                                                                                                     |
| 5. Проверка результата         | «Проблема решена?» → нет: другой сценарий; после 2 неудачных — специалист                                                                                                                                                                      |
| 6. Передача специалисту        | «Позвать специалиста» всегда под рукой; сводка из 6 пунктов; статус «У специалиста»                                                                                                                                                            |
| Контр-фича                     | **Пульт поддержки** `/support` (вход «Специалист» с кодом): меню-очереди (Все · Новые · Мои · В работе · Ждут пользователя · Решённые), режимы «Доска» и «Чат», только сводка ИИ + переписка после передачи, ответ приходит в чат пользователя |

Тестовые сценарии кейса → поведение: простое (вопрос) — ответ и сразу «Готово»; неоднозначное — вопросы
только о недостающем; несколько симптомов — шаги, при неудаче другой подход, затем специалист;
нерешаемое — сразу сводка специалисту; срочное — без лишних вопросов, первым шагом обходной путь.

API: `POST /api/llm/triage | support-questions | steps | handoff` (JSON-схемы), см. `apps/api/src/llm/`.
Тёмная тема — по умолчанию (светлая — переключателем).

## ИИ и автодвижение (этапы 3–4)

- Сервер: `apps/api/src/llm/` — клиент Ollama (`/api/chat`, стриминг NDJSON, structured outputs по JSON-схеме,
  `think: false` с автоматическим откатом для моделей без поддержки), промпты по шагам (ТЗ, п. 10), демо-режим.
  Эндпоинты: `GET /api/llm/status`, `POST /api/llm/classify | questions | plan`, `POST /api/llm/stream` (SSE).
- Клиент: `apps/web/src/features/agent/agent.ts` — оркестратор. Движение карточки задаёт приложение, а не
  служебные маркеры модели (надёжнее с локальными моделями):
  - **A** чёткая+лёгкая — Черновик → Уточнение (транзит) → В работе → Проверка → Готово без остановок
    (настройка «Автопринимать лёгкие задачи»);
  - **B** чёткая+трудная — план ⏸ → выполнение по шагам (маркеры `<step>N</step>` → галочки) → Проверка ⏸;
  - **C** размытая+лёгкая — вопросы с вариантами ⏸ → ответ → Проверка ⏸;
  - **D** размытая+трудная — вопросы ⏸ → план ⏸ → выполнение → Проверка ⏸ (3 контрольные точки).
- Окно задачи — `apps/web/src/features/task/`: панель 45 % / весь экран / mobile, markdown, подсветка кода
  токенами палитры, копирование, перегенерация, «Стоп», переименование, смена типа, удаление.
- Пока без базы данных: задачи и переписка — в браузере (localStorage), сервер stateless.
  На этапе 6 оркестратор переедет на сервер (очередь), чтобы задачи шли при закрытой вкладке.

## Дизайн-токены

- Палитра в духе интерфейса Claude — `packages/tokens/src/palette.ts`: крем, песок, камень, крафт, терракота,
  ржавчина, графит, чернила. Смысловые токены обеих тем — `packages/tokens/src/themes.ts` (единственный источник:
  из него генерируется `tokens.css` и по нему же идёт проверка контраста, `npm run check:contrast`).
- В Tailwind стандартная палитра отключена — доступны только токены (`bg-canvas`, `text-fg`, `bg-primary` и т. д.).
- Тёмная тема по умолчанию; переключатель: системная / светлая / тёмная (`localStorage`, ключ `kc-theme`).
- Основная кнопка: светлая тема — ржавчина + крем (4.66:1), тёмная — терракота + чернила (5.9:1).

## Бат-Форум (ТЗ v4.3, п. 16)

«Бат-Форум» в меню — форум в стиле Reddit: слева «о сообществе» (описание, статистика, правила, «Создать тему»),
по центру поиск и лента (сначала рекомендации «Для вас», при вводе запроса — результаты), справа за чертой —
сообщества б/почта, б/доступы, б/сеть, б/железо, б/программы, б/разное. Темы, ответы, «Полезно», решение (автор
или специалист), закрепление и удаление (специалист). Рекомендации учитывают задачи пользователя («Похоже на ваше
обращение»). При наборе обращения показываются похожие темы; у ответов и тем — «Спросить лично»
(Бат-общение). Сервер: `apps/api/src/forum`, клиент: `apps/web/src/features/forum`.

## Бат-общение (ТЗ v4.19, п. 18)

Не мессенджер: личный вопрос по теме Бат-Форума тому, кто в ней отвечал, — кнопка «Спросить лично» у темы
или ответа. Кто спросил — спрашивает, кто принял — помогает. Переписка закрывается через 3 дня тишины или
7 дней с начала, по «Проблема решена» (спрашивающий) или «Больше помочь не могу» (помогающий) и уходит в
архив — копия в кабинете каждого, оттуда «Спросить снова». Удалить — у обоих сразу. Одному человеку — не
больше 3 вопросов в сутки, в «Настройках» можно не принимать личные вопросы. ИИ и специалисты переписку не
читают; по жалобе специалист видит только последние 10 сообщений нарушителя. Сервер: `apps/api/src/dm`,
клиент: `apps/web/src/features/dm` и `apps/web/src/pages/MessagesPage.tsx`.

## Разделы (ТЗ v3.3 и v4.6, п. 5)

- Все задачи — в «Общем»; разделы — подборки из него. «Новый раздел» в меню: название, как пополняется,
  описание, цвет. **«По смыслу»** — раскладывает ИИ; **«Вручную»** (индивидуальный раздел) — обращения
  выбираете вы: «Добавить обращения» (галочки и поиск) в шапке раздела и в «⋯», «Показывать в разделах»
  в меню обращения. «⋯» у раздела — изменить, добавить обращения, разложить заново (только «по смыслу»),
  удалить (задачи остаются).
- ИИ раскладывает задачи: `POST /api/llm/sort` (`apps/api/src/llm/`, промпт `SORT`, пачки по 8 задач;
  без модели — по совпадению основ слов). Клиент — `apps/web/src/features/sections/sorter.ts`.
- В меню карточки — «Показывать в разделах» и «Убрать из «…»»: убранную задачу ИИ туда больше не добавит
  (`Task.hiddenFrom`). Задача, созданная на доске раздела, сразу попадает в него.

## Доска (этап 2)

- Данные — демо, в браузере (`apps/web/src/features/board/store.ts`, Zustand + localStorage, ключ `kc-board`).
  Кнопка ↻ в шапке доски возвращает демо-данные. Бэкенд подключится на этапах 3–4.
- Перетаскивание (dnd-kit): мышью — за любое место карточки; пальцем — долгое нажатие;
  клавиатурой — фокус на ручке ⋮⋮, пробел, стрелки, пробел (Esc — отмена).
- Назад по доске = «доработать»: диалог «Что доработать?», отмена возвращает карточку на место.
- Меню «⋯» на карточке — перемещение в любой столбец без перетаскивания (удобно на телефоне).
- Mobile: столбцы — сворачиваемые секции со счётчиками; «Готово» по умолчанию свёрнуто.
- Перелёт карточки между столбцами — Motion `layoutId`, 320 мс; при `prefers-reduced-motion` отключается.

## Обои доски

Под доской — обои в духе фона чата в мессенджерах: градиент из 4 точек (`--wallpaper-1…4`)
и оригинальный контурный узор (карточки, облачка чата, галочки, скрепки, листики).
Узор — бесшовная плитка `apps/web/src/assets/wallpaper-doodles.svg`, применяется как CSS mask,
цвет задаёт `--wallpaper-ink`, поэтому тёмная тема перекрашивает его сама.
Столбцы полупрозрачные (`--column`); контраст текста проверяется поверх каждой точки градиента.
Пересобрать узор: `npm run wallpaper -w @app/web`. Включение: `<AppShell wallpaper>`.

## Логотип

Знак — летучая мышь, висящая вниз головой на перекладине (как обращение на доске); сложенные крылья —
три столбца доски. Используется только через
`<Logo variant="full" | "mark" tone="color" | "mono" />` (`apps/web/src/brand/Logo.tsx`).

- Геометрия — `apps/web/src/brand/markGeometry.ts` (один источник для компонента и иконок).
- Цвета — токены `--logo-primary` (чернила; в тёмной теме крем) и `--logo-accent` (терракота).
- `tone="mono"` — один цвет (currentColor) для цветных плашек и приглушённых мест.
- Favicon и PWA-иконки: `npm run icons -w @app/web`.
- Подпись авторов «Канбат made by Code Invaders» — `<MadeBy />` со знаком команды `<TeamMark />`
  (`apps/web/src/brand`, исходник — `docs/brand/code-invaders.png`): внизу меню и на экране входа.
